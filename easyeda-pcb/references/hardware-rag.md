# On-demand hardware reference library

Use the bundled [hardware RAG command](../scripts/hardware_rag.py) to download selected hardware documentation or reference designs, retain their originals, and retrieve cited passages locally. The corpus directory is supplied separately from the skill. Use it as a personal or project library and store it wherever the files are authorized to be retained.

## Download the free PCB ebooks

```sh
skill_dir=/path/to/easyeda-pcb
python3 "$skill_dir/scripts/hardware_rag.py" download-ebooks --output ./pcb-ebooks
```

Choose a directory outside `easyeda-pcb/`. The command fetches the four titles below and reuses existing PDFs at the destination. Use repeatable `--book` options to select specific titles. Run ingestion separately if you want to search the PDFs through RAG.

## Adapt an official reference design

1. Match the manufacturer's design to the exact part, package, silicon revision where applicable, and intended interface or operating conditions. Check the current datasheet and errata. Review the official schematic, layout, BOM, and assembly notes when available. If the available design is unsuitable, use the applicable datasheet, errata, and hardware guide, and record the design assumptions.
2. Record the publisher URL, design revision, and the blocks reused. Retain applicable notices when copying design files or artwork. Note changes to pin assignments, parts, power, clocks, stackup, or routing that affect the reference's assumptions.
3. Recheck the affected electrical, layout, and firmware requirements. On a custom RP2350A board, for example, verify the crystal, flash and GPIO assignments against the Pico SDK board definition. Include USB enumeration, BOOTSEL/UF2 flashing and SWD in prototype bring-up when those interfaces are present. Report compatibility at the level confirmed by the available checks.

## Ingest selected files

Use Python 3.9 or later with SQLite FTS5 and JSON support. Install `pypdf` in the Python environment doing the ingestion for PDF text extraction. HTML, text, ZIP inventory and retrieval use Python's standard library. Downloads accept public HTTPS links, including HTTPS redirects. Use direct document or archive URLs and keep access tokens out of the manifest.

Create a JSON manifest with a `sources` array. Every entry needs a stable lowercase `id`, `vendor`, `title`, `kind`, `revision`, `parts` (a JSON array of part or family labels), and a `url` or `path`. Relative file paths are relative to the manifest. With both fields present, `path` supplies the original and `url` records its publisher. Use a different ID for revisions you want active side by side. For an extensionless download, set `format` explicitly. Supported kinds are `guide`, `datasheet`, `errata`, and `reference-design`. Supported formats are `pdf`, `html`, `text`, `zip`, and `artifact`. The revision is recorded as supplied. Check it against the retrieved title page, revision history, or board marking before relying on it. Add the optional `sha256` field to pin an already verified set of bytes and reject unexpected changes.

The manifest below shows a public guide and a separately obtained design archive. Replace the archive filename and revision with the actual local file and board revision.

```json
{
  "sources": [
    {
      "id": "esp32-s3-layout",
      "vendor": "Espressif",
      "title": "ESP32-S3 PCB Layout Design",
      "kind": "guide",
      "revision": "v1.8",
      "parts": ["ESP32-S3", "ESP32-S3-WROOM-1"],
      "url": "https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/pcb-layout-design.html"
    },
    {
      "id": "esp32-s3-devkitc-reference",
      "vendor": "Espressif",
      "title": "ESP32-S3-DevKitC-1 Reference Design",
      "kind": "reference-design",
      "revision": "v1.1",
      "parts": ["ESP32-S3", "ESP32-S3-WROOM-1"],
      "path": "downloads/esp32-s3-devkitc-reference.zip",
      "url": "https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html"
    }
  ]
}
```

```sh
export EASYEDA_RAG_DIR=/path/to/pcb-reference-library
python3 "$skill_dir/scripts/hardware_rag.py" ingest sources.json
python3 "$skill_dir/scripts/hardware_rag.py" list
```

The library contains a SQLite index and checksum-addressed originals. A successful re-ingest replaces the active passages for that source ID. Byte-identical artifacts share the same stored file for a given format, and changed originals remain available by checksum. A failed fetch or a refresh that loses all extractable text leaves the earlier indexed source active. The import reports per-source errors and warnings. After fixing an extraction dependency or an OCR text layer, re-ingest the corresponding file under the same source ID.

## Retrieve and use evidence

```sh
python3 "$skill_dir/scripts/hardware_rag.py" search \
  'antenna keepout' --part 'ESP32-S3' --content-type text --limit 6
python3 "$skill_dir/scripts/hardware_rag.py" search \
  --source esp32-s3-devkitc-reference --content-type inventory
```

Search uses local full-text ranking and supports exact manifest filters for part/family, vendor, kind, and source ID. Search results contain the passage, content type, vendor, title, supplied revision, original and resolved URL when available, local artifact path, checksum, and PDF page or archive member when applicable. If an exact filter yields no results, inspect the registered part tags and use the documented family or source ID. Query the guide and the reference design separately when both are applicable.

Use the retrieved text as evidence for the requested design question. Put the cited PDF page, figure, or archive member next to the PCB decision. Verify any numeric value, by-revision difference, table, image, or rule drawn from a schematic or layout in the original. Check the device and package, board revision, population options, stackup, and fab limits before adopting a reference design decision. For an EasyEDA layout, record the resulting requirement in the [PCB design rulebook's rule sheet](design-rules.md) and verify the implemented design.

PDF extraction indexes existing text. Scanned documents need a text layer or separate notes. ZIP packages retain all original bytes and index their filenames and supported textual members. macOS archive metadata is omitted from the index. Native EDA boards, Gerbers, drawings without text and nested archives need inspection in their appropriate viewer. Add original engineering notes with their document revision and page or design locator for decisions found only in graphics or CAD.

## Use another retrieval backend

```sh
python3 "$skill_dir/scripts/hardware_rag.py" export > pcb-passages.jsonl
```

Each JSONL record includes a stable passage identifier for the same source, checksum, locator and text. The export includes text, metadata and inventory records. Use this as input to an approved embedding or vector index if desired. For a refreshed source, replace that source ID's old external records with the current export so stale passages leave retrieval. Keep the provenance fields in the destination and apply the source's usage conditions to any shared service.

## Connect the library to Codex over MCP

The [MCP server](../scripts/hardware_rag_mcp.py) uses the same SQLite library as the CLI. It exposes `list_hardware_sources` and `search_hardware_references` over stdio. Run ingestion through the CLI before connecting. Searches use the latest committed index, so you can ingest more files while a client is connected.

From a workspace that contains `easyeda-pcb/`, set up Python 3.11 or newer and install the dependencies. Skip the setup commands when the local virtual environment is already prepared. [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)

```sh
uv venv --python 3.13 .pcb-rag-venv
uv pip install --python .pcb-rag-venv/bin/python 'mcp>=2,<3' pypdf fonttools
```

For a PDF you already have, create a manifest using `path` as shown in [Ingest selected files](#ingest-selected-files). Run these commands from the workspace root.

```sh
.pcb-rag-venv/bin/python -B easyeda-pcb/scripts/hardware_rag.py \
  --library ./pcb-reference-library ingest ./sources.json

codex mcp add easyeda-rag -- "$PWD/.pcb-rag-venv/bin/python" -B \
  "$PWD/easyeda-pcb/scripts/hardware_rag_mcp.py" \
  --library "$PWD/pcb-reference-library"
```

Start a new local Codex session. Codex launches the stdio process when it connects. Ask for a search such as “Find cited layout guidance about a differential pair crossing a plane split.” Use `codex mcp list` to check registration and `/mcp` in the Codex terminal UI to check the active connection. [Codex MCP setup](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
